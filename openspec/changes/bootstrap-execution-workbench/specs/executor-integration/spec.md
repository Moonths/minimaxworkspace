# Spec Delta

## Purpose

为工作台提供可替换的任务执行通道，使用户能够安全地连接自托管 ComfyUI，并始终清楚当前操作发生在模拟环境还是真实远程环境。

## ADDED Requirements

### Requirement: 执行器模式必须明确可见

系统 SHALL 提供模拟执行器与 ComfyUI 远程执行器两种模式，并在工作流提交前及执行记录中持续显示本次实际使用的模式。系统 MUST NOT 将模拟结果表述为真实远程生成结果。

#### Scenario: 默认进入模拟模式

- **WHEN** 用户首次打开未配置远程地址的工作台
- **THEN** 系统显示模拟执行器为当前模式并说明其结果仅用于流程验证

#### Scenario: 切换执行器

- **WHEN** 用户选择另一种可用执行器模式
- **THEN** 系统立即更新当前模式标识及连接区域
- **AND** 已输入的工作流内容不得被清空

### Requirement: 远程连接配置必须可验证

系统 SHALL 允许用户配置通过 HTTP 或 HTTPS 访问的 ComfyUI 基础地址，并能够主动执行健康检查。远程地址 MUST 仅由服务端用于连接，不得要求浏览器直接访问 ComfyUI API。

#### Scenario: 健康检查成功

- **WHEN** 用户对已启动且网络可达的 ComfyUI 地址执行健康检查
- **THEN** 系统显示连接成功及可用的服务状态信息

#### Scenario: 地址格式无效

- **WHEN** 用户提交非 HTTP 或 HTTPS 地址
- **THEN** 系统拒绝执行健康检查并给出可修正的格式提示

### Requirement: 未配置远程模式必须可识别

当用户选择远程执行器但尚未提供有效地址时，系统 SHALL 显示未配置状态并禁止提交远程任务，同时 MUST 保留模拟模式作为可用选择。

#### Scenario: 未配置时尝试远程提交

- **WHEN** 用户在远程地址为空时尝试提交任务
- **THEN** 系统不发起远程请求并提示先完成连接配置

### Requirement: 连接失败必须返回可操作反馈

系统 SHALL 区分网络不可达、响应超时、非成功响应及无法识别的服务响应，并向用户显示不包含敏感信息的失败原因。

#### Scenario: 远程服务不可达

- **WHEN** 健康检查因网络错误或超时失败
- **THEN** 系统显示连接失败及检查 Tailscale、ComfyUI 启动状态和地址的提示
- **AND** 系统不得把该状态显示为已连接
