# Spec Delta

## Purpose

使用户能够从工作台导入并执行 ComfyUI API 格式工作流，持续跟踪每次任务，且在页面刷新后仍能追溯输入、执行状态和输出结果。

## ADDED Requirements

### Requirement: 工作流导入必须校验 API 格式

系统 SHALL 支持粘贴或选择 JSON 文件导入工作流，并在提交前验证其为由节点组成的对象，每个节点包含有效的 `class_type` 与 `inputs`。系统 MUST 在无法识别格式时拒绝提交并指出原因。

#### Scenario: 导入有效工作流

- **WHEN** 用户导入符合 API 格式的工作流 JSON
- **THEN** 系统显示工作流名称、节点数量及可提交状态

#### Scenario: 导入界面格式或损坏 JSON

- **WHEN** 用户导入无法解析的 JSON 或不符合 API 节点结构的界面工作流
- **THEN** 系统显示格式错误或 API 格式提示
- **AND** 系统不得创建执行任务

### Requirement: 每次执行必须保存不可变输入快照

系统 SHALL 在提交时保存工作流内容、工作流名称、执行器模式和创建时间，执行记录 MUST 不受后续编辑器修改影响。

#### Scenario: 提交后修改编辑器

- **WHEN** 用户提交工作流后又修改编辑器中的 JSON
- **THEN** 原执行记录仍保留提交时的完整工作流快照

### Requirement: 任务状态必须可持续跟踪

系统 SHALL 使用排队、运行、成功、失败四种主要状态展示任务，并允许用户刷新当前任务和最近记录。远程任务 MUST 保存 ComfyUI 返回的远端任务标识以支持后续查询。

#### Scenario: 模拟任务完成

- **WHEN** 用户使用模拟执行器提交有效工作流
- **THEN** 系统创建可追溯记录并依次更新任务状态
- **AND** 成功后显示明确标注的模拟结果

#### Scenario: 页面刷新后查看记录

- **WHEN** 用户在任务创建后刷新页面
- **THEN** 系统仍能显示该任务及其最近一次已知状态

### Requirement: 远程结果必须通过工作台读取

当远程任务完成后，系统 SHALL 从 ComfyUI 历史记录中提取输出文件引用，并通过工作台后端提供结果访问，避免要求浏览器直接连接远程服务。

#### Scenario: 远程任务产生输出

- **WHEN** ComfyUI 历史记录包含已完成任务的图片或视频输出
- **THEN** 工作台显示可访问的结果项、文件类型和文件名

#### Scenario: 完成任务没有输出

- **WHEN** 远程任务已完成但历史记录没有可识别输出
- **THEN** 系统显示任务已完成但未发现结果，而不是伪造预览

### Requirement: 执行失败必须保留诊断信息

系统 SHALL 将提交校验失败、远程拒绝、执行错误和结果查询异常记录为可查看的失败信息，且 MUST NOT 将完整远程地址中的凭据或敏感配置写入执行记录。

#### Scenario: 远程执行失败

- **WHEN** ComfyUI 拒绝任务或返回执行错误
- **THEN** 系统将任务标记为失败并显示可诊断的错误摘要
- **AND** 工作流快照和执行器信息仍可供用户检查
