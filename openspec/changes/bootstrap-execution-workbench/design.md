# Design

## Context

当前仓库只有基础前后端与空能力规格，动机见 `proposal.md`。首版需要同时支持可重复的本地验证和未来 Tailscale 远程联调，但没有真实 MiniMax H3 API 工作流可供本次验收。工作台后端与 ComfyUI 必须分离：浏览器只访问工作台，工作台服务端再访问远程服务。

## Goals / Non-Goals

**Goals:**

- 用同一组前端流程覆盖模拟执行器和 ComfyUI 执行器。
- 将远端协议、状态与输出格式隔离在执行器边界内。
- 让运行记录可恢复、可追溯，且结果文件不需要浏览器直连 ComfyUI。
- 在没有真实工作流时仍能完成确定性的自动化验证。

**Non-Goals:**

- 不实现 WebSocket 实时进度、任务取消、多用户权限和 Windows 常驻 Agent。
- 不实现自然语言理解、VideoSpec 编译、分镜编辑或任意节点参数映射。
- 不把真实 MiniMax H3 生成标记为已验收。

## Decisions

### 1. 采用服务端执行器接口，而非浏览器直连 ComfyUI

定义统一的查询健康、提交任务、查询任务和读取结果边界，分别由模拟实现与 ComfyUI 实现承担。这样前端不感知远端 URL、HTTP 协议细节或跨域问题，后续也可增加 Windows Connector 而不改创作界面。

备选方案是浏览器直接请求 Tailscale 地址，但其会引入 CORS、混合内容、地址暴露和结果文件访问问题，因此不采用。

### 2. 首版使用按需轮询，而非引入后台 worker

前端在活动任务存在时轮询工作台的同步接口；服务端向 ComfyUI 查询队列与历史，或将模拟任务按经过时间推进，并把最新状态写回数据库。页面重新打开时可再次同步。

这避免了首版引入 Redis、常驻进程和分布式锁。代价是没有用户访问时状态不会主动刷新，但下一次查询可以恢复，不影响最终记录。

### 3. 工作流与运行快照分别持久化

`workflows` 保存用户最近编辑和导入的工作流；`runs` 保存提交时的完整 JSON 快照、模式、远端任务 ID、状态、错误摘要和输出元数据。运行记录仅逻辑关联工作流，不依赖其后续内容。

使用 MySQL JSON 字段保存工作流与输出元数据，日期类型由 Drizzle 推断并通过 tRPC/Superjson 传递，避免重复定义不一致的数据库实体类型。

### 4. ComfyUI 使用 HTTP 提交与历史恢复

远程提交采用 `POST /prompt`，请求体包含 API 格式 `prompt` 和工作台生成的 `client_id`；状态恢复使用 `/queue` 与 `/history/{prompt_id}`。首版不依赖 WebSocket，因此断线或页面刷新后仍可通过远端任务 ID 恢复结果。

健康检查使用 `/system_stats` 与 `/queue` 的基本响应判断，不用“端口能打开”代替真实服务验证。

### 5. 结果文件通过受控的后端代理读取

运行记录只保存 ComfyUI 返回的文件名、子目录、类型与展示元数据。结果代理根据运行 ID 和结果索引取出受信记录，再请求远端 `/view`，不接收浏览器任意构造的远程文件地址。

首版支持 ComfyUI 历史中常见的 `images`、`gifs` 和 `videos` 输出集合；无法识别的输出保留为空并明确提示。

### 6. 模拟执行器只生成协议级演示结果

模拟任务使用确定性的状态迁移和本地 SVG 结果，用于验证界面、持久化和结果展示。所有模拟结果在界面和元数据中带有 `simulated` 标识，不上传远程地址，也不伪造视频文件。

### 7. 配置与安全边界保持单用户、私网假设

ComfyUI 地址仅允许 HTTP/HTTPS，拒绝 URL 内嵌用户名和密码；默认地址来自服务端环境变量，界面输入可覆盖本次连接。由于产品可能部署在不可信网络的风险暂不由首版解决，README 必须明确仅用于受控私网，不能直接暴露公网。

## Risks / Trade-offs

- [轮询造成状态更新不够实时] → 活动任务使用短间隔刷新，后续以增加 WebSocket 的独立 OpenSpec 变更改进。
- [不同自定义节点的输出结构不一致] → 只标准化已知输出集合，无法识别时明确显示无结果；真实工作流联调后补充适配。
- [任意远程地址可能形成 SSRF] → 限制协议、禁止 URL 凭据、只允许服务端访问，并明确私网部署边界；公网部署前必须增加访问控制与地址策略。
- [模拟结果被误认为模型效果] → 全局模式标识、运行记录和结果元数据同时标注模拟来源。
- [真实 MiniMax H3 参数映射仍未知] → 首版只提交完整 API 工作流，不猜测节点名称；下个变更使用已验证 JSON 建立显式参数映射。

## Migration Plan

1. 新增工作流和运行记录表，通过 `npm run db:push` 在开发环境同步。
2. 更新 `.env.example` 与本地 `.env`，真实地址仅写入未提交的本地配置。
3. 先使用模拟模式完成提交、刷新恢复和结果验证，再配置远程地址做健康检查。
4. 本次数据库变更为纯新增；回滚应用代码可保留空表，不执行破坏性删表。

## Open Questions

- 真实 MiniMax H3 工作流中提示词、尺寸、时长和种子的节点映射，待拿到已验证 API JSON 后确定。
- ComfyUI 是否经过额外鉴权代理，待真实环境联调时确认；首版不内置特定鉴权方案。
