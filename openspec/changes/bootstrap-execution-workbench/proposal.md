# Proposal

## Why

项目需要一个可持续迭代的创作工作台，但当前首先缺少一条可验证的执行主线：从工作台配置执行器、提交 ComfyUI API 格式工作流，到跟踪任务并查看结果。先建立这条纵向闭环，可以避免在真实远程生成尚未跑通前，过早堆叠对话、分镜和通用节点编辑界面。

## What Changes

- 建立桌面端优先的工作台首屏，集中展示执行器、工作流、当前任务和最近执行记录。
- 提供统一的执行器边界，首版包含明确标识的模拟执行器与 ComfyUI 远程执行器。
- 支持配置 ComfyUI 地址、执行健康检查，并清晰区分未配置、连接成功和连接失败。
- 支持粘贴或导入 ComfyUI API 格式工作流 JSON，执行前校验其基本结构。
- 支持提交任务、查询任务状态、查看错误和生成结果；模拟模式不得被描述为真实远程验收。
- 持久化工作流快照与执行记录，使每次运行可以追溯执行器、输入和状态。
- 使用 OpenSpec 管理本次及后续行为变更，首版不实现自然语言转 VideoSpec、多分镜编辑、组件市场和通用节点编辑。

## Capabilities

### New Capabilities

- `executor-integration`: 定义执行器选择、远程连接配置、健康检查及真实与模拟模式的明确区分。
- `workflow-execution`: 定义 API 格式工作流导入、校验、提交、状态跟踪、执行记录和结果读取。

### Modified Capabilities

无。

## Impact

- 前端：React 工作台页面、连接配置、工作流编辑、任务状态与结果视图。
- 后端：Hono/tRPC 路由、执行器接口、模拟执行器、ComfyUI HTTP 客户端与轮询。
- 数据：工作流与执行记录表，保存必要快照而非仅保存远端任务 ID。
- 配置：新增 ComfyUI 与默认执行器相关环境变量示例；密钥和本地地址不提交到 Git。
- 外部系统：通过 Tailscale 可达的自托管 ComfyUI；真实 MiniMax H3 工作流联调依赖后续提供的已验证 API JSON。
